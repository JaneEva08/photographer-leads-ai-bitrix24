# ИИ-разбор заявок для частного фотографа

MVP для типового частного фотографа в России: заявка клиента за минуту превращается в лид в Битрикс24 с разобранной карточкой, проверенной датой, ориентиром цены и черновиком ответа.

📋 Отчёт по домашнему заданию: [HOMEWORK.md](HOMEWORK.md)

Фотограф вымышленный, все данные синтетические. Прайс и календарь меняются под конкретного заказчика в `data/`.

## Две страницы, два входа заявки

| Страница | Для кого | Что делает |
|---|---|---|
| `/` | клиент | калькулятор: тематика, дата с проверкой занятости, часы, опции, автоматические скидки → «Проверьте заявку» → «Отправлено, фотограф подтвердит». Это заявка, а не заказ: цена предварительная |
| `/admin` | фотограф | разбор заявки свободным текстом (из мессенджера, письма, звонка), карточка, пересчёт с персональной скидкой и сохранением в лид |

```
Текст:       форма → маскировка → GigaChat → правила (дата, цена, нужен ли человек) → подстановка → Битрикс24
Калькулятор: параметры → правила → (GigaChat только для комментария клиента) → подстановка → Битрикс24
```

Заявка из калькулятора уже структурирована, поэтому нейросеть ей нужна только если клиент написал комментарий. Без комментария ответ собирается по шаблону. Это прямая иллюстрация принципа «где хватает правила, ИИ не нужен».

### Расчёт и скидки

Один расчёт `rules.quote()` для калькулятора, разбора текста и пересчёта у фотографа. Браузер цену не считает, только показывает: сервер всегда пересчитывает сам, поэтому клиент не может подменить сумму.

- Опции: выезд за город, срочная обработка (+30 %), второй фотограф (свадьба и мероприятие), дополнительные кадры в ретушь.
- Автоматические скидки: фотосессия в будний день −10 %, свадьба больше чем за 180 дней −5 %, вместе не больше 15 %.
- Персональная скидка (до 30 %, с причиной) — только у фотографа в `/admin`. Кнопка «Сохранить в Битрикс24» обновляет сумму лида и пишет расшифровку в ленту.
- Если дата занята, предлагаются ближайшие свободные (для свадьбы и мероприятия — только пт–вс).

Все цифры — в `data/prices.json`.

| Шаг | Кто | Что |
|---|---|---|
| Форма | автоматизация | имя, телефон, email идут сразу в CRM, в нейросеть не передаются |
| Маскировка (`app/privacy.py`) | автоматизация | имена, телефоны, email, адреса, ники, ссылки, ИНН в тексте → метки `[ИМЯ_1]`, `[ТЕЛЕФОН_1]`… |
| Разбор (`app/ai/`) | ИИ (GigaChat) | тематика, дата, место, длительность, бюджет, тип заявки, чего не хватает, черновик |
| Правила (`app/rules.py`) | автоматизация | свободна ли дата, ориентир цены по прайсу, решение «нужен фотограф лично» |
| Битрикс24 (`app/bitrix.py`) | автоматизация | лид (с пометкой «калькулятор» и расчётом в комментарии), задача «ответить клиенту», уведомление |
| Фотограф | человек | проверяет черновик, ведёт свадьбы, жалобы и бронь |

Главное архитектурное решение: **дату и цену считает код, а не нейросеть.** ИИ только извлекает параметры из текста, поэтому не может пообещать занятую дату или выдумать цену.

## Установка

Нужен Python 3.11+.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate
pip install -r requirements.txt
```

## Настройка `.env`

```bash
cp .env.example .env      # Windows: copy .env.example .env
```

1. **GigaChat.** В личном кабинете [developers.sber.ru](https://developers.sber.ru/portal/products/gigachat-api) → проект GigaChat API → «Настроить API» → «Получить ключ». Ключ — в `GIGACHAT_CREDENTIALS`.
2. **Сертификат.** Скачайте корневой сертификат НУЦ Минцифры на [gosuslugi.ru/crt](https://www.gosuslugi.ru/crt), положите в папку `certs/` и укажите путь в `GIGACHAT_CA_BUNDLE_FILE`. Без него будет ошибка «Сервис GigaChat недоступен».
3. **Битрикс24.** «Приложения» → «Разработчикам» → «Входящий вебхук», права `crm`, `task`, `im`. Базовую ссылку (до последнего слэша) — в `B24_URL`. Пока поле пустое, приложение работает без CRM и пишет об этом в карточке.

4. **Пароль фотографа.** `ADMIN_PASSWORD` закрывает `/admin` и служебные API (логин `admin`). Пусто — открыто всем, только для локального запуска. Калькулятор клиента остаётся публичным.
5. **Дата для демо.** `APP_TODAY=2026-10-23` фиксирует «сегодня»: иначе скидка за раннюю бронь и свободные даты со временем меняются и расходятся с протоколом.

Ключи и ссылку вебхука никому не отправляйте и не показывайте на скриншотах. `.env` в git не попадает.

## Запуск

```bash
uvicorn app.main:app --reload
```

Откройте http://127.0.0.1:8000 — калькулятор клиента, http://127.0.0.1:8000/admin — рабочее место фотографа. При старте в терминале видно, работает ли вебхук Битрикс24.

В режиме `DEMO_MODE=true` после отправки заявки из калькулятора под подтверждением показывается, как её увидит фотограф: карточка с панелью пересчёта и текст, ушедший в нейросеть.

## Тесты

```bash
pytest
```

Автотесты проверяют анонимизатор, правила цены и даты, клиенты GigaChat и Битрикс24 и сквозную обработку. Сеть им не нужна: нейросеть и CRM в них подменены. Ручные сценарии гоняются только на настоящем GigaChat — протокол в `TEST_PROTOCOL.md`.

## Мониторинг: Loki + Grafana

Логи приложения уходят в Grafana Loki, дашборд в Grafana показывает заявки, сбои GigaChat и Битрикс24 и все записи с поиском. Мониторинг необязателен: при пустом `LOKI_URL` приложение работает как раньше, логи только в консоли.

```bash
cd monitoring
cp .env.example .env          # задать GRAFANA_ADMIN_PASSWORD
docker compose up -d          # Loki на :3100, Grafana на :3000
```

В корневом `.env` проекта: `LOKI_URL=http://localhost:3100/loki/api/v1/push`, затем запустить приложение как обычно. Grafana — http://localhost:3000, логин `admin`. Источник Loki и дашборд «Заявки фотографа — мониторинг» подключаются сами (`monitoring/grafana/provisioning`).

Наполнить дашборд без GigaChat и CRM: `python monitoring/demo_events.py` — синтетические события с меткой `app="photo-leads-demo"`.

**Как устроено** (`app/loki.py`):
- обычный обработчик `logging`: всё, что приложение пишет в лог, идёт и в консоль, и в Loki через `POST /loki/api/v1/push`, без агента Promtail;
- отправка в фоновом потоке пачками раз в секунду, с таймаутом. Loki недоступен — заявки обрабатываются дальше, записи для Loki теряются, в консоли предупреждение;
- метки (`app`, `env`, `level`, `event`) — только с короткими списками значений; подробности события — JSON в строке лога;
- в Loki не уходят тексты заявок, имена и контакты: событие `lead_processed` содержит только тип, тематику, источник, статус CRM, время обработки и число замаскированных ПДн. Телефоны и email в любой строке дополнительно маскируются;
- не отправляются логи `httpx` (иначе запрос в Loki логировал бы сам себя) и `uvicorn.access` (IP посетителей);
- Loki хранит логи 14 дней, порты Loki и Grafana открыты только на `127.0.0.1`.

| Событие (`event`) | Когда |
|---|---|
| `lead_processed` | заявка обработана (текст или калькулятор) |
| `ai_error`, `ai_bad_json` | GigaChat не ответил / вернул неверный JSON |
| `crm_error`, `crm_warning` | Битрикс24 не принял лид / не создал задачу или уведомление |
| `bad_input` | клиент ввёл неверные данные |
| `manager_saved` | фотограф сохранил пересчёт в лид |
| `app_started`, `app_stopped` | запуск и остановка |
| `log` | прочие записи приложения |

## Журнал анонимизации

`logs/privacy_log.csv`: время, маскированный текст и количество меток каждого типа. Исходный текст и словарь соответствия в журнал не пишутся, иначе он сам стал бы хранилищем персональных данных.

## Структура

```
app/
  main.py        страницы и API (калькулятор, разбор, пересчёт)
  pipeline.py    порядок обработки заявки
  privacy.py     маскировка и обратная подстановка
  rules.py       прайс, календарь, передача человеку
  bitrix.py      клиент Битрикс24
  loki.py        отправка логов в Grafana Loki
  ai/            провайдер ИИ (GigaChat) и промпт
data/            прайс и календарь занятости
static/          index.html — калькулятор, admin.html — рабочее место, card.js — карточка с пересчётом
tests/           pytest
monitoring/      Loki + Grafana: docker-compose, конфиги, дашборд, демо-события
```

Чтобы заменить GigaChat на другую модель, достаточно новой реализации с методом `complete(system, user)` в `app/ai/`.

## Ограничения MVP

- Источник заявок — только форма; мессенджеры подключаются отдельно.
- Анонимизатор работает на правилах и словаре имён: редкие имена без заглавной буквы и не из формы может пропустить. Поэтому есть журнал для выборочной проверки.
- Календарь — JSON-файл, а не CRM-календарь фотографа.
- `/admin` защищён одним общим паролем (`ADMIN_PASSWORD`, basic auth), без учётных записей. Публичные `/api/calc/*` пока без лимита запросов: на сервере поставьте rate limit (например, в Nginx).
- Если нейросеть недоступна, заявка из калькулятора всё равно попадает в CRM: комментарий клиента уходит как есть, лид помечается «нужен фотограф лично». Исходный текст заявки всегда сохраняется в комментарии лида.
- Из черновика ИИ автоматически убираются предложения с ценами и статусом даты, а при передаче человеку — и обещания брони.
- Подтверждение клиенту после решения фотографа пока отправляется вручную; автоматизировать можно через смену стадии лида в Битрикс24.
